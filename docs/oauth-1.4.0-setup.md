# Локальное обновление 1.4.0 — Яндекс OAuth

Новый главный экран «Галерея» и вход с часов через браузер телефона без установки Home на телефон.

## Настройки OAuth-приложения

19.10.2026 настройки ниже уже сохранены в аккаунте владельца и проверены повторным открытием формы. После установки достаточно нажать «Войти» на часах и завершить вход на телефоне. Шаги ниже оставлены как инструкция для восстановления.

Client ID остаётся `3701c105243844eea0598102c2b09a84` (WearHome). Создавать новое приложение или менять Client ID не нужно.

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/), выберите WearHome и редактирование платформ.
2. В «Веб-сервисы» добавьте Redirect URI:

   ```text
   https://wear.googleapis.com/3p_auth/com.dynorixz.smarthome
   ```

   Сохраните прежний `dynorixzsmarthome://oauth/callback` для входа в браузере самих часов. Адрес из Китая нужен только для китайских Wear OS: `https://wear.googleapis-cn.com/3p_auth/com.dynorixz.smarthome`.
3. В Android у пакета `com.dynorixz.smarthome` добавьте SHA-256 нового сертификата:

   ```text
   73:67:BA:27:02:15:19:4A:AD:1B:2C:77:D6:9A:28:E8:49:17:6A:AD:A8:B6:AB:BD:D2:1D:5E:FD:48:78:8E:ED
   ```

   Прежний `FE:3F:1A:B3:AE:59:52:8B:B7:6F:6A:9C:8E:81:00:6E:29:ED:48:E4:B3:C6:CD:54:5E:B1:6B:41:CD:74:4D:CA` можно сохранить для пользователей старых APK. Отпечаток — публичный идентификатор сертификата, он не заменяет приватный ключ подписи.
4. Оставьте права `iot:view` и `iot:control`, сохраните изменения.
5. Соедините часы с телефоном, откройте Home на часах и нажмите «Войти». Продолжите в браузере телефона. После разрешения доступа результат вернётся на часы, и устройства загрузятся.

В браузерном PKCE-входе сертификат APK не передаётся Яндексу: для этого способа критичен зарегистрированный Redirect URI. Android fingerprint хранится отдельно в Android-настройках OAuth и пригодится при использовании нативной интеграции. Смена подписи не меняет аккаунт Яндекса и устройства умного дома. Переустановка очищает локальный вход, избранное и настройки часов — потребуется войти снова.

На странице Wear OS может появиться дополнительная кнопка `ALLOW` / «Не выходить». Она возвращает результат в штатное приложение часов на телефоне. Служебная схема этого системного ответа нормализуется только внутри callback `RemoteAuthClient`, при совпадении пути пакета. Затем проверяются исходный `state`, срок сессии, однозначность параметров и PKCE; внешние deep link проходят прежнюю строгую проверку адреса.

Проверено на Galaxy Watch SM-L355F с удалённым Home на сопряжённом телефоне: Galaxy Wearable вернул схему `com.samsung.wearable.watchuniteplugin`, исходный `state` совпал. После нормализации прошли обмен кода на токен и проверка доступа к реальному дому (19.10.2026). Токены, коды и значения state в диагностику не выводятся.

При первой проверке 19.10.2026 в приложении был только старый callback. Затем в существующем WearHome добавлены HTTPS-адрес возврата и новый отпечаток. Старые адрес и оба прежних отпечатка сохранены. Права `iot:view` и `iot:control` не менялись.

## Подпись следующих обновлений

Оригинальный ключ FE:3F:… не найден. Для этой сборки создан новый постоянный release-ключ (RSA 3072), оба APK подписываются им. Последующие обновления необходимо подписывать тем же новым ключом — тогда повторная переустановка не потребуется.

Файлы подписи находятся вне репозитория:

```text
<закрытая папка владельца>\dynorixz-smarthome-release.jks
<закрытая папка владельца>\dynorixz-smarthome-release.password.dpapi
```

Пароль зашифрован Windows DPAPI для текущего Windows-пользователя. Эти два файла нельзя удалять. DPAPI-файл сам по себе не обеспечивает перенос на другой компьютер: для миграции нужна отдельная защищённая резервная копия с доступным владельцу паролем. Приватный ключ и пароль не входят в публичный проектный архив; публичный сертификат сохранён со сборкой.
